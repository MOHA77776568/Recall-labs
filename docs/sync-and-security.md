# المزامنة والخصوصية

## ما الذي يُشارك؟

التطبيق يبدأ ببيانات محلية؛ لا يرسلها تلقائيًا. المزامنة اليدوية تربط ملف البيانات المحدد في GitHub ببيانات جهازك، وتشمل المجموعات والمحاضرات والبطاقات وحالة المراجعة. تحتفظ الواجهة الأصلية بجدولة مراجعاتها. استخدم نفس المستودع والفرع والمسار على اللابتوب والأجهزة الأخرى لتشارك مساحة عمل واحدة. المرفقات الثنائية، مثل PDF، لا تدخل في ملف مزامنة JSON وتُحفظ محليًا. لا تتضمن مزامنة البيانات تحديث ملفات البرنامج.

الوجهة الافتراضية هي `MOHA77776568/Recall-labs`، الفرع `main`، الملف `data/workspace.json`. يمكن استخدام مستودع خاص مستقل للبيانات، وهو الموصى به لمحتوى شخصي. الكتابة إلى مستودع عام تحتاج تفعيل الموافقة الصريحة في إعدادات التطبيق. لا تخزّن معلومات حساسة في مستودع عام؛ كل نسخة سابقة تُكتب إلى Git قد تبقى في سجل المستودع حتى بعد حذف البطاقة.

## إعداد الصلاحيات

1. في إعدادات حساب GitHub افتح **Developer settings → Personal access tokens → Fine-grained tokens**.
2. اختر المستودع المطلوب فقط، وحدد تاريخ انتهاء مناسبًا.
3. امنح **Contents: Read and write** لرفع التغييرات. القراءة من مستودع عام لا تتطلب رمزًا؛ المستودع الخاص يحتاج رمزًا يملك حق القراءة.
4. أدخل الرمز في إعدادات التطبيق المحلي. لا تحفظه في Git، ولا ترسله في المحادثة.

قد يحتاج الرمز إلى موافقة المؤسسة إن كان المستودع تابعًا لمؤسسة. تمنح بعض إعدادات حماية الفرع قراءة فقط أو تمنع الكتابة المباشرة؛ عند رفض GitHub للمزامنة راجع صلاحيات الرمز وسياسة الفرع. لا تمنح صلاحيات أوسع لمجرد معالجة خطأ اتصال.

مصادقة GitHub المتاحة للمساعد أثناء التطوير لا تنتقل إلى تطبيق Windows. الرمز المحلي مستقل، ويمكن إلغاؤه من GitHub دون تغيير حساب المحادثة.

في نسخة Electron يحفظ التطبيق الرمز عبر `safeStorage` عند توفر تشفير نظام التشغيل. في Windows يعتمد ذلك على حماية حساب Windows؛ لا يشكّل حاجزًا أمام برنامج خبيث يعمل بصلاحيات حسابك. نسخة المتصفح لا تحفظ الرمز بين إعادة تحميل الصفحات.

## التعارض والحذف

إذا عدّل جهازان البطاقة نفسها دون مزامنة، يعرض التطبيق تعارضًا ويطلب اختيار النسخة المحلية أو نسخة GitHub. راجع المحتوى قبل الاختيار، ثم أكمل المزامنة. يحتفظ تنسيق البيانات بعلامات حذف حتى لا تُعاد بطاقة محذوفة بسبب نسخة أقدم على جهاز آخر.

يحاول التطبيق استخدام مراجعة الملف الحالية عند الكتابة إلى GitHub. إذا تغيّر الملف أثناء العملية، تتطلب المزامنة إعادة القراءة والتوفيق بين التغييرات بدل الكتابة فوق تحديث جديد. لا تكرّر الضغط على المزامنة عدة مرات بالتوازي.

عند تعديل البيانات بواسطة مساعد أو أداة أخرى، اتبع [تنسيق البيانات](data-format.md)، وحافظ على معرّفات البطاقات وتواريخ التعديل وعلامات الحذف؛ لا تستبدل الملف كاملًا ببيانات لا تراعي البطاقات الموجودة. الاختبارات في المستودع توثّق الحالات المتوقعة للمزامنة.

## النسخ الاحتياطي ونقل بيانات الموقع السابق

صدّر JSON احتياطيًا قبل استيراد مجموعة كبيرة أو اختيار نتائج تعارض عديدة. جرّب الاستيراد على نسخة احتياطية وتحقق من المحتوى بعده. ملف GitHub نسخة مشتركة، وليس بديلًا عن نسخة احتياطية مستقلة.

حُفظت ملفات الواجهة الأصلية لتعمل محليًا، لكن الموقع السابق يطلب تسجيل الدخول بحساب ChatGPT للحصول على مساحة عمل حسابك. لا يمكن للمساعد استخراج تلك البيانات من ملفات الواجهة العامة، ولم نختلق بطاقات بديلة.

حين تستطيع فتح الموقع السابق، انقل بياناتك بالخطوات التالية:

1. من الموقع السابق افتح **Data & settings → Download JSON backup** واحفظ الملف.
2. من الواجهة المحلية افتح **Data & settings → Import CSV or JSON**.
3. اختر **JSON cards / full backup** وحدد الملف، ثم **Preview → Restore backup** وراجع رسالة التأكيد.
4. تحقق من البطاقات والمجموعات والتقدم قبل المزامنة مع GitHub.

يحافظ هذا المسار على بنية المجموعات والمحاضرات والبطاقات وجدولة المراجعات الأصلية. يتضمن التصدير الأصلي تنبيهًا بأن المرفقات غير مشمولة؛ انقل ملفاتها بشكل منفصل. لا يمكن للتطبيق المحلي قراءة تخزين موقع على نطاق مختلف مباشرةً، ولا يحتاج بعد النقل إلى تسجيل الدخول بحساب ChatGPT.
